# sts-rl-2 建仓评估计划

## 建议

值得为当前主路径单独建仓。第一版只做一件完整的事：从一份已知的 Ironclad 整局训练存档出发，继续游戏，按既有规则搜索和学习，保存后从同一局面接着走，并能用冻结模型评估整局表现。程序入口、数据流、存档格式、测试和运维可以重新设计。已经验证的游戏规则、模型计算、搜索内核和关键反例是新仓的起点。逐张牌重写、逐个 CUDA 内核重写，会把本来可以直接对照的东西也变成未知数。

评估以 COMBAT49 第 501 轮和通过完整两轮验证的双进程 full480 组合作为第一份样本。新仓可以在未来支持别的模型、算法和硬件。第一版的范围由这条能交付的路径决定。老实验、它们的入口、参数和专用测试都留在 sts-rl。旧仓在切换前仍是现役工作的落点；切换以后，旧提交、工作日志、存档和实验材料仍可按原地址查到。

## 已知成本和第一个疑点

本次核对时，集成分支是 c8595e76，GPU 实验分支是 62d010dc。历史最佳双进程组合两轮用时 465.06 秒，同一起点复测用时 495.56 秒。两次的第二慢机器，第 502 轮分别用时 214.97、215.95 秒，第 503 轮分别用时 215.28、219.65 秒。全组总时间还受首次采样前的启动时间影响。[四卡完整对照](../../worklog/2026-11-18.md#combat49-best-control-reproduction)

本机的 `runs/local/fourfold128-20261117/best-repo-final-sources.json` 列了 418 个文件，含 117 个 configs 文件、20 个 rl/_compat 文件和 12 个 bridge 文件，sim 文件为零。旁边的 `prepare_best_repo_runtime.py` 将 sim 链接到 joint-rule-8/sim。GPU 构建还要从一份单独的源码快照取规则。这个包适合重现实验，但不能直接充当新仓的文件清单。尤其是 bridge 内的状态规范可能属于运行依赖，真实游戏客户端则是另一项功能。[GPU 构建入口](../../rl/search/full480/frame_modules.py#L7)

工程编排和文档重写可行性高。风险集中在两个地方：离开旧目录后能否重建原生组件，以及旧存档隐含了多少 Python 类名、环境状态和随机数状态。先用小原型回答这两个问题，再给整个迁移报价。

## 什么进新仓

| 处置 | 第一版的内容 |
|---|---|
| 沿用经过验证的实现 | 主路径使用的模拟器规则与原生绑定、模型前向、CPU/GPU 搜索计算、PPO 数学和匹配当前行为的测试。保留来源提交、第三方声明和许可。打包器把某个模块顺带装进来，不算入选理由。 |
| 重新编写 | 环境与搜索之间的数据交接、训练与评估入口、实验配置、存档与恢复编排、构建和运行材料的获取方式、日志。先保持原有计算与动作含义，再逐处简化。 |
| 一次性转换 | 选定的 v1 存档在固定的 v1 环境中读取，导出权重、Adam、随机数、训练进度和各环境的在途状态。v2 只读自己的格式。转换器和原档摘要可以留在归档侧，转换产物记录来源。 |
| 归档于旧仓 | 非当前路线的训练器、旧监督目标、消融、旧模型、启动脚本和实验专页。真实游戏客户端、看牌界面、研究面板暂列此栏；实际用到的纯数据或编解码逻辑按职责提取。候选以后重新进入主线时，以当时的问题和测试重新接入。 |

收件依据有三份：从冷启动跟到保存、普通恢复、冻结评估的实际调用；原生编译所用的传递依赖；公共行为所需的游戏规则和边界用例。一批种子没抽到的牌或事件，仍可能属于主路径。旧日志中只有坏例子或验收方法仍有价值时，只迁相应的用例。

## 基础设施从四种职责开始

| 职责 | 拥有什么 | 对外承诺 |
|---|---|---|
| 游戏 | 整局状态、规则、游戏随机数、合法动作和快照 | 给一个合法动作就前进一步；用快照恢复后，可以继续走原来的局。策略只看到玩家可见的信息。 |
| 决策 | 模型推理、战斗搜索、分支随机数和本轮冻结的权重 | 给定局面、预算和权重版本，返回动作。需要训练或解释时，同时给出候选顺序、评分和选择依据。 |
| 学习 | 实走轨迹、搜索提供的教学数据、回报计算和优化器 | 输入一批数据，完成规定的更新并发布下一版权重。搜索替玩家选的动作、假想分支、自然终局和采样段末尾都有各自清楚的含义。 |
| 运行 | 环境槽、批处理、多卡同步、失败处理、存档和测量 | 按一份配置组织采样、更新、存档和恢复。单机与四机共用同一轮训练逻辑，机器差异由运行层处理。 |

四块放在一个仓库、一个版本内。可以先写普通函数和少数数据类；保留已经验证的双搜索进程和批处理方式。第一版对用户只给训练、冻结评估、固定输入回放三个操作。回放直接调用同一套决策代码。新模型接决策模块，新学习目标接学习模块。等第二个实际用例出现，再提取重复部分。是否替换 SB3，先看主路径实用到哪些能力及存档转换结果；这项选择不必绑住建仓。

每次运行保存一份完整生效配置，记录源码版本、规则和模型材料的摘要、种子、工作量、设备与结果位置。机器地址和凭据由运行环境提供。Git 放可构建源码、锁定依赖、小测试及材料清单，大存档和原始性能输出按摘要取回。四机存档在全部分片写好后才发布完成标记；保存中断还能取回上一代。监控读取运行输出里的结构化事件，人的 worklog 可以自由改写。

## 按风险顺序评估

| 顺序 | 评估工作 | 得到什么才算完成 |
|---|---|---|
| 1. 固定旧版参照 | 固定第 501 轮输入、真实源码及编译输入、每机校准表、实际命令、记录过的搜索请求与两轮结果。对照现有归档并核实可取回的文件。 | 一张按用途划分的清单，列出主路径、一次性转换、留档和缺失材料。每个外部件有来源、摘要、获取或构建办法。 |
| 2. 做两个最小原型 | 在没有旧仓检出的干净环境重建一个可运行的战斗；用含中途选牌和待执行效果的局面走 CPU，并以相同输入回放 GPU。另将指定旧存档转成 v2 能读的状态。 | 同一局面的候选身份、动作、随机数和后继状态相符。转换后各机在途局面、观察、模型和 Adam 对得上，第一次预测可用。记录依赖了哪些旧 Python 类名和外部材料。 |
| 3. 打通最短训练流程 | 从正常入口采样、做一次更新、记指标、写存档；在新进程恢复后接着采样。另用同一接口跑冻结整局评估。 | 固定样本的动作、行为概率、搜索目标和回报可逐项核对；更新后的权重与 Adam、恢复后第一批动作和随机流对齐。故意中断一次保存，验证上一代仍可恢复。 |
| 4. 上同硬件作最终判断 | 复用成熟的四卡双进程配置和原验收标准，从 501 开始，每卡 128 环境 × 768 步，预算 256/256/1024、覆盖率 100%、选牌容差 0.05，做两轮并普通恢复 503。 | 每轮 393,216 行、8 次 Adam；同轮四卡一致。固定回放核对动作、Q、教师、随机数和原浮点容差；自由调度沿已有判据。比较第二慢机器、全组墙钟与启动/采样/更新/保存分项。边缘差异做相同条件的交错复测。 |
| 5. 决定切换 | 把验收过的正式入口、恢复命令和仍有意义的问题放在 v2 的 main。旧仓记录最后参照提交；并行期间主路径修复按单个改动同步，切换当天核对两边新增改动。 | 下一位从空目录能构建、复现一次决策、恢复指定存档，并找到当前任务。旧运行继续可用至切换完成。 |

前两步是可行性评估的交付边界。任一原型失败，就把缺口定在“哪个文件无法取得”“哪个状态没有导出来”或“哪种运算结果变了”，估一次修复成本，再决定照原计划重写还是先把对应旧组件固定为独立依赖。若要靠带上整套旧工作区才能继续，先解决那个具体依赖。等模型与规则已经对上，再判断是否值得重写热点。

粗排期按单人专注工作量计，先给清单半天到一天，干净构建和存档原型再留一到三天。外部材料取得顺利是这个估算的前提。第一条完整主路径暂按周规划，等原型完成后再给天数。四卡两轮对照每臂历史用时约 8 分钟，新旧各跑一臂约需 1.1 GPU 小时；编译、短测、等待机器和边缘结果复测另计。复用已有且条件匹配的记录可以减少重跑。

## 项目怎么管

- main 指向已通过主路径检查的版本；每次重要实验保存来源提交、生效配置、存档和结果。实验产物先存好，成熟改动连同测试回主线。机器上临时改过的代码能否从仓库重建，属于实验交付的一部分。
- README 让人从空目录走到第一次回放、训练和恢复。模块文档解释长期接口。一张 TODO 表只列仍需决策或动手的工作，做完后留下结果链接。
- 每天一份 worklog。每件事一个标题，开头两三句写“做了什么、发现什么、所以怎么定”；未完时写下一个人该从哪里接。命令、提交和证据放末行。只有改变结论的限制才写，只有启动、暂停、切换、恢复或需要人介入时才报运行状态。v2 取消每天另写 handoff 的要求，接手者直接从 worklog 和 TODO 继续。
- 影响正在进行的工作的用户决定在 TODO 或当前事项里记一次；落实时链接结果。性能实验给固定预算和可复现输入。程序行为改动与对应回归一起提交。

**日志示例，采用 11 月 18 日实际数据**

> **模型有九成把握时，仍会漏掉不少搜索改选**
>
> 回放了 31,440 个战斗局面。模型给首选动作至少 90% 概率时直接出牌，可以跳过原来 53.1% 的搜索原子决策，也会漏掉 850 次改选里的 337 次。先保留固定预算。下一项比较这些改选值多少，再决定哪些局面可以少搜。
>
> 复现见 [当日搜索成本与回放记录](../../worklog/2026-11-18.md#algorithm-infra-search-value)。

第一笔投入应该花在干净构建和存档转换上。它们过了，重写就是一项有边界的工程；它们卡住时，多设计一层框架并不能缩短迁移。
