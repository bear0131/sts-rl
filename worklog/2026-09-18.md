## Audit upper-policy sampling mismatch between training and evaluation

User intention: “帮我调查一下当前训练和测试是否有上层统计差异：训练的时候上层决策是随机采样的、测试的时候上层决策是 argmax 固定的”. Scope is a read-only behavior/statistics audit plus one bounded local diagnostic, not a change to training, evaluation defaults or the running cluster campaign. Acceptance is to trace the actual current `u40x16` collection and formal eval entrypoints, separate upper from combat ownership, determine whether the difference is real, and state what existing evidence can and cannot quantify. Persistent matched evaluation is tracked as TODO EVAL01.

Static result: the mismatch is real. `AccumulatingMaskablePPO._collect_nosl_is_az_rollouts` constructs the masked categorical distribution and calls `get_actions(deterministic=False)` for every environment; native search subsequently replaces only combat-phase actions, so non-combat actions remain ordinary PPO samples. The current distributed run is inner-only: `configure_nosl_is_az_inner_only` freezes shared/overworld and leaves only the combat specialist trainable, consistent with the independent final audit in this log where shared9+overworld123 tensors equal the supplied upper and combat83 differ. Thus this is not an active upper-PPO optimization mismatch; it is a state-visitation mismatch for combat training, because sampled upper actions determine decks, routes, HP, relics and potions seen by the combat learner.

Formal `rl.evaluation.eval` has opt-in `--stochastic`; absent that flag, `policy_strategy` constructs `PolicyStrategy(..., deterministic=True)`. The split policy delegates to SB3's masked categorical `get_actions`; deterministic mode calls `mode()`, and `MaskableCategoricalDistribution.mode()` is masked probability argmax. This deterministic policy is the default upper component for policy/native/rules solvers and for model fallback under overworld rules. The safe-route arm is an explicit exception for map decisions, and upper-rules decisions are a different policy rather than a sampled copy of the training upper. The recorded BASE01 manifest also says deterministic policy; no current formal commands used `--stochastic`.

Existing training/eval payloads do not record upper `p_max`, entropy or non-argmax rate. NOSL entropy metrics are combat replay diagnostics, while inner-only disables upper PPO updates. Therefore historical logs prove the behavior difference but cannot quantify its visitation effect. A bounded diagnostic used the supplied upper `hier_hp_ppo_999817216_steps.zip` (SHA256 `7bfbf0cab4fa08f140a8d7654895c23eaa47b7024a78658805a8a1199da47b5f`) on already-development seeds20000–20007, A0, CPU1, eight argmax plus eight sampled episodes, max6000 steps/180s per arm. To avoid contaminating the result after local v3/native schema mismatches failed loudly before completing any row, the successful probe held combat to the same checkpoint's deterministic policy and changed only upper action selection. Runtime: Python3.11.15, Torch2.12.0+cpu, NumPy2.4.6, Gymnasium1.0.0, sb3-contrib2.9.0; explicit `build-gumbel311-run` extension SHA256 `d2fb626687286251ffc0b854c0d9123750608f3bb5862d16923486b7e3506e3d`.

### Curve interpretation

The act curves are rolling episode outcomes, not direct learner losses. Each rank retains its last
100 finished episodes; the distributed record averages the four rank-level means. Early points are
therefore biased toward short early deaths while longer surviving runs have not finished, and the
window is warming up. The rising initial shape does not by itself prove rapid learning or a logging
fault. It also lacks a published per-rank denominator, so very early fractional means should not be
given binomial confidence claims.

The matched-step gap is nevertheless real and too large to dismiss as only warm-up. At step491520,
new versus old is21.75% versus52.25% act1 clear,0.50% versus8.75% act2 clear, and mean floor16.68
versus23.37. Floor15 pass rates are75.75% versus88.00%, but floor20 is20.50% versus50.75%, placing
most of the divergence around the Act1 boss/early Act2 boundary. At step540672 the new run remains
at20.50% act1,0.50% act2 and floor16.61. The training diagnostics do not show corruption at the
matched step: finite fraction is1 in both; new/old policy entropy1.241/1.231, target entropy

The supported interpretation is that the frozen deterministic rule upper changes route/deck/event

model upper. Prior frozen-checkpoint evaluation with a stronger combat candidate does not guarantee
