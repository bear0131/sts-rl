- 人工表示：最新训练 schema 上限为 14 类别列/26 连续列，但旧模型按实际输入宽度兼容，不能认为每个已部署模型都使用这些字段。`mapfeat.py:68` 逆拓扑 DP 直接算后续最少/最多精英数、最近休息点距离，并加相对位置、可达性、Boss 身份；数值 cap/scale=15。`encoder.py:100` 及事件 builder 把事件效果结构化为 HP/金币/牌/遗物/药水得失，缺完整结构字段时有文本正则 fallback。卡牌主要由可学习 ID embedding 表示；`card_kind` 类型/稀有度为可选输入，不能把启发式卡牌评分表说成 PPO 直接输入。当前 Ironclad champion 的特性为 `card_mods,reward_upgrade`，未启用 `card_kind/card_bundles`。
- 人工目标：`rewards.py:70,79,120` 默认终端 base 为 `0.5 * floor / normalizer + 0.5 * won`（normalizer A0–A9=45、A10=46，进度不截顶），因此目标包含进度，不是纯胜率。HP 0.1、升级数 0.035、遗物数 0、offset -0.307 属非终端 potential；终端 shaping 清零、gamma=1 下望远镜抵消，不能说成最终无条件奖励囤血/升级。`trainer.py:128,640` 另外加默认系数0.1的路径目的房间辅助交叉熵。
- **实际动作会受人工规则影响**：`sts2-rs/crates/sts2-runai/src/ppo/policy.rs:1114,1179` 与 `python/ppo_decode.py` 的 group-mass decode 默认 ON；仅将商店删牌、变牌、附魔、smith 四类按意图汇总概率，先选组再选组内最大项。不是修改 logits，也不是学习出的分组。`net_policy.py:83` 训练仍按逐候选概率采样，`net_greedy` 仍为普通 argmax；不能把这两个评测路径和部署 grouped decode 等同。
- 规则护栏/桥接差异：`env.py:278` 过滤满药水栏时商店买药的无效动作；`policy/mod.rs:2649,2711` 在 Rust 组合策略中对已选事件动作做 lethal veto：若预览会死亡则换成可存活且掉血最少的选项，全致死/无法确认时不替换。`python/realgame_ppo.py:892` 则在模型前过滤致死选项，和 Rust 后替换不是同一干预；`realgame_ppo.py:827` 对不在白名单、非 INITIAL 的事件后续页强制选首个可识别退出项（如存在），这是明确的手工接管。标准 Python PPO env 的普通 `step` 直接执行网络动作，不经过 Rust 组合策略的局外 veto。没有据静态源码宣称这些分支在当前真实运行中触发多少次。
- 可选人工策略：`ppo/policy.rs:1022` 的 `RunNudge` 默认空，可按幕对跳过选牌加 log-prob 偏置、在 HP 达阈值时把休息改成升级；仅为实验入口。`policy/mod.rs:2624` 配置药水 OC 后按价值规则接管交换，无表时可交网络；交换 surface 本身另有 flag。`policy/heuristic.rs` 保留整套人工 V/卡牌与遗物特征、事件先验、路径枚举、商店收益/金币背包、休息比较，服务规则基线、expert/BC 和战斗 fallback；不能把它当作默认 PPO 多候选上层决策器。`ppo/bc.py` 支持 expert warm-start，不据其存在推定每个 champion 的训练谱系。
