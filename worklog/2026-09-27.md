## BASE04 shared-embedding fallback audit and rule completion

### 用户原始意图、范围与验收条件

用户要求调查在 inner-only NOSL 中打开外层/内层共享部分的冻结（即启用
`--nosl-is-az-train-shared-embeddings`）后，会影响哪些仍由 checkpoint fallback 决定的
外层动作；随后用一些简单策略填补当前 `ironclad-overworld-v1` 未处理的状态。

本轮范围是共享 card/relic/potion embedding 到外层 logits 的静态与可复现运行时审计，以及
公共上层规则、测试和说明的增量修改。不启动、停止、恢复或修改任何训练，不改变战斗搜索、
observation/action codec、奖励或 value target。规则只在能从公开状态和合法动作候选明确判断时
接管；仍不明确的状态必须继续显式 fallback，不能用固定 action index 猜测事件语义。

验收要求：列出被共享 embedding 影响的外层状态/动作族与实际 fallback 证据；新增规则对每个
接管状态返回合法、确定且可解释的动作；现有已覆盖规则行为保持不变；剩余未知状态仍返回
`None`；worker、evaluation 和 Watch 继续复用同一规则入口；相关 unit/integration 测试通过。
本节随当前提交。

### 调查结论

`rl/training/distributed_sb3.py` 的 `--nosl-is-az-train-shared-embeddings` 只在
inner-only NOSL 路径启用。加载后先由
`rl/algorithms/accumulating_ppo.py::reset_nosl_is_az_shared_embeddings()` 用 run seed
重置 `core.shared` 下所有 `nn.Embedding`，再由
`configure_nosl_is_az_inner_only(train_shared_embeddings=True)` 解冻这些表；外层
specialist、card/relic/potion projection 和 policy 其他部分仍冻结。标准 split policy
的三张共享语义表是 card、relic、potion，本轮增加回归锁定这一边界。

`rl/policies/split_policy.py` 的外层 encoder 在每个 phase 都输入常驻 deck、held relic
和 held potion token。因此共享表变化会直接改变候选实体指针动作 `USE_POTION`、
`PICK_CARD`、`REWARD_CARD`、`REWARD_RELIC`、`REWARD_POTION`、`SHOP_CARD`、
`SHOP_RELIC`、`SHOP_POTION`、`BOSS_RELIC`；也会经 Transformer 上下文化的 global
token 间接改变 map/event/proceed/chest/campfire/Neow 等固定按钮 logits。在规则上层
配置中，只有 `rank_overworld()` 返回 `None` 的状态才实际暴露给冻结模型 masked argmax，
所以 shared embedding 重置后最不稳定的是这些 fallback。

实现前使用 `sim/sts_lightspeed/build-eval-t5`、seeds 10000--10063、8 个常驻环境、
规则战斗和规则上层运行 64 局；fallback 临时取最小合法动作，仅用于继续收集。133 秒内
记录 90 次 fallback：88 次事件、2 次 `BONFIRE_SPIRITS` card-select。后者已有
`remove_value()` 分值，却被 card-select context allowlist 提前拒绝，是确定的规则漏口。
事件 fallback 主要为 Mysterious Sphere、Vampires、Forgotten Altar、Tomb of Lord Red
Mask、Drug Dealer/Augmenter、WeMeetAgain、Falling、Masked Bandits、Face Trader、
Sensory Stone、Note For Yourself、Mushrooms、Designer、Duplicator、Woman in Blue 和
Nloth。

### 实现

- 上层规则升为 `ironclad-overworld-v2`；worker、evaluation 和 Watch 仍复用
  `env/search/overworld_rules.py` 的唯一入口。
- 放行 `BONFIRE_SPIRITS`，复用现有公开候选卡与 `remove_value()`，不读取隐藏事件字段。
- 为 Drug Dealer/Augmenter、Duplicator、Face Trader、Forgotten Altar、Masked Bandits、
  Mushrooms、Mysterious Sphere、Sensory Stone、Woman in Blue、Tomb of Lord Red Mask、
  Vampires 增加简单确定性分值。只使用事件名、当前/最大生命、金币、持有遗物、药水空槽
  和实际 legal mask；规则不会返回不合法按钮。
- Falling 未公开随机 attack/skill/power 的具体牌，N'loth 未公开两件候选遗物，
  We Meet Again 未公开指定 potion/card/gold，Note For Yourself 未公开将取得的牌，
  Designer 的随机服务模式和动态价格也未公开；这五类继续返回 `None`，避免凭 action
  index 猜语义。
- `env/search/README.md` 持久记录共享 embedding 的直接/间接影响面与 v2 fallback 边界；
  dashboard 展示和现役测试同步新版本。


结果：`89 passed, 1 skipped, 2 subtests passed`；skip 是测试自身声明的 CUDA 条件，CPU
objective 测试仍执行。原生整局测试显式加载 `build-eval-t5`，没有把旧扩展缺字段当作通过。

## BASE04 public dynamic event candidates

### 用户纠正、范围与验收条件

用户在上一阶段保留五类事件 fallback 后明确纠正：“缺少公开候选信息你应该填补上而不是继续交给模型”。本轮据此把 Falling、N'loth、We Meet Again、Note For Yourself、Designer 在按钮上已经公开的动态候选补进 canonical public state，并让上层规则按真实候选决策。缺字段、字段类型错误或 legal/detail 不一致仍须整屏 fail closed；不按固定动作下标或本地化字符串猜测。保持现有 observation tensor/checkpoint schema 不变，不启动、停止、恢复或修改运行中的 TRAIN23。

### 实现与契约

- `sim/sts_lightspeed/bindings/slaythespire.cpp` 新增 `event_option_details()`，直接从事件初始化时已固定、`ConsoleSimulator` 已展示的字段导出 action-aligned typed details：Falling 的具体待失去卡，N'loth 的两件候选遗物，We Meet Again 的药水/金币/卡牌，Note For Yourself 的待取得卡，以及 Designer 的服务模式与动态成本。它只枚举当前 native legal event actions，不暴露 RNG 或未揭示结果。
- `bridge/schemas/combat_state.py` 将 native card enum 规范成 canonical card id，放在 `options.event_choices`。`env/core/encode.py` 不读取该附加字段；新增逐字段数组相等回归确认同一 canonical state 有无 `event_choices` 时 observation tensor 完全相同。
- `bridge/real_game_env.py` 可透传 action-aligned typed event option 扩展，但本机 `CommunicationMod.jar` 的 `GameStateConverter.getEventState()` 经 `javap` 确认 stock schema 只有本地化 `text`/`label`、`disabled`、`choice_index`。因此 stock real bridge 不从按钮文字猜 card/relic/potion id，缺 typed details 时规则按上述契约 fallback。
- 上层规则升为 `ironclad-overworld-v3`：Falling 丢最低价值公开牌；N'loth 只用低价值候选换 Gift；We Meet Again 比较具体药水、金币和牌；Note 比较取得牌和随后删牌机会；Designer 比较公开价格、可选升级/删除与 HP 代价。规则只对实际 legal option 打分，候选缺项时不接管。
- 审查 Designer transition 时确认现有模拟器 option 1 漏扣界面显示的金币，option 3/4 又因缺 `break` 贯穿后续 case。本轮不把这一既有模拟器语义缺陷混入公开候选任务；v3 将这三个不可靠分支保守置低分，仍从公开合法按钮中选安全 option 0/2/5，而不是回退模型。

最终结果为 `100 passed, 1 skipped, 2 subtests passed`（62.58 秒）；skip 是既有 CUDA 条件，CPU objective 仍执行。规则 unit 单独为 `47 passed`，包含 native 64-seed contract 的 integration 单独为 `3 passed`。其中第一次 runner 的 60 秒预算在本机超时，固定工作量不变、仅把 runner 预算提高到 120 秒后 70.14 秒完成；随后一次组合套件触发全局 120 秒 pytest timeout，故该固定 64 局测试单独声明 180 秒上限，最终组合套件在 62.58 秒内通过，仍不改变测试工作量。
