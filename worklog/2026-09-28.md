## Enemy-state identity and Centurion/Healer comparison

用户追问当前模型如何读入敌人状态，以及如何合理比较 Centurion+Healer 都存活与 Centurion 死亡、Healer 存活。核对真实链路：`env/core/encode.py` 明确使用固定 monster slots，slot i 同时是 action target i；普通死敌不从列表过滤，因此 Centurion/Healer 的 slot 不因存活状态重排。C++ packed native path 同样跳过的只有 `MonsterId::INVALID`，普通 `isDeadOrEscaped()` 敌人仍写入同一 slot 的 id/scalars。

当前 language-free checkpoint 的每个 monster slot 输入包括：categorical `monster_id`、当前 move、intent category；六个 scalars（present、当前 HP、HP ratio、block、按当前 intent 计算的 adjusted incoming damage、hit count）；monster buffs/status 向量。`SplitStSPointerPolicy` 将这些拼成一个 monster token，再加 slot positional embedding；target action 使用同一 slot。死敌不是完全 PAD：id/move 仍在，present=0、HP=0，native decoder 还会按 present 清零 buffs。模型没有跨时间 persistent entity UUID；同一场普通 Centurion+Healer 中可用“slot+monster_id”稳定识别 Healer，但跨场只能说是同一类 Healer。

合理比较分三层：
1. 首选有效 matched boundary：相同 player/hand/piles/relics/potions/turn、相同 Healer slot/id及其 HP/block/intent/status，仅让 Centurion 的状态不同；从同一 `BattleContext.clone()` 分支执行真实动作，避免只改 HP 造成死亡计数、enemy-turn schedule、Healer 行为不一致。
2. 做模型输入敏感性时，可保留真实死敌 token 的 `present=0` 版本，并额外做一个明确标注的 dead-slot→PAD ablation；后者只回答“残留 dead Centurion token 是否影响模型”，不能当作合法游戏状态胜率。
3. 输出应分开记录 `forward_root` 的 direct model V、对 Healer-targeted/end-turn action 的 logits/probability，以及 search 的 selected action/Q；不能用 search 回传值代替 direct V。比较 Healer 时按原 slot 对齐，不按 alive 列表排序；若遇 Gremlin split 等特殊重排场景另行记录 slot remap。

建议的最小诊断表：`Healer slot/id` 是否相同、Healer HP ratio/block/intent/status 是否相同、Centurion present/HP/intent、`ΔV_direct`、Healer-target action logit delta、End-Turn logit delta、search action/Q delta；同时报告 dead-slot 保留与 PAD ablation 两种结果。

End Turn 的真实 pre-draw boundary 预览（仅用于语义核对）为玩家 HP=5、energy=0、`post_enemy_turn_boundary=true`、Centurion 仍 2 HP，模型 direct V=0.0471；它没有显示出一个把 boundary 错标成高价值的明显固定 bug。生产 strict 配置不在该 boundary 停止，而是完整执行 enemy phase/start-of-next-turn 后继续搜索，故 root End Turn Q 还混合了隐藏 world-line 和后续 player-turn value。

当前归因：

1. 立即原因（高置信）：Full-Gumbel strict 的根选择规则把 End Turn 的搜索 Q/完成 Q 与访问数结合后推过了低 prior 的斩杀动作；这是搜索层行为，换 PUCT/End-Turn leaf 即明显改变结果。
2. 放大器（中高置信）：End Turn 的后续分支 value 明显高于 direct root prior（End Turn sample Q 约 0.10，而 root direct V 约 0.044），说明 value head/后继分支对“下一回合仍可活、可继续出牌”的估计偏乐观；但单个 root 尚不足以区分 value 校准误差与隐藏 world-line 的真实收益。
3. 训练可修复部分（中置信）：combat value target 是整场结束时的 final HP/200（输=0），根样本在战斗结束后统一赋值；因此模型理论上能通过更多覆盖“低 HP、敌人可斩杀、End Turn 会输”的样本学到风险，但这是稀疏的 delayed target，且 direct root value 不带动作条件，不能单靠根 value 解决某个动作的短期风险。
4. 设计层限制（高置信）：动作选择实际由 search 的 complete-action Q 决定，而训练 policy target / dashboard 常看 direct logits；两者不是同一决策量。Full-Gumbel 的 completed-Q min-max 归一化会把很小的 raw-Q 差异放大到 0.1×(50+visits) 的尺度，再在 visits 打平时决定动作，容易把价值估计噪声转成确定性 End Turn。
5. 尚无证据表明是“永久局部最优”或 simulator 把 Centurion/Healer 状态读错：固定 slot、目标映射、End Turn bits、真实 HP/intent 都已核对；step 391/392/393 的选择也会变化，说明不是不可自我修复的死锁。

未决但不影响当前归因：需要正式的多状态 paired calibration（同一 hand/HP/intent，比较 Strike lethal、Defend、End Turn 的 successor value 与最终 HP target）才能量化“训练量可修复”的比例；暂不扩大测试或修改代码。

### 因果归因

这个反例给出一个明确方向：搜索错误可以先发生。固定未来消除了同一 root 下 world-line 重采样差异，Bash 首个后继直出 V 也不低，Full-Gumbel 仍能仅因候选预算/Gumbel/早期不可逆淘汰而排除它。因此不能把所有反直觉行为解释成“value 先错，搜索只是忠实保留”。

但 Centurion 2 HP 反例仍显示另一入口：根部 direct policy 并不偏好 End Turn，End Turn 后继/搜索 Q 的相对乐观再被 completed-Q 的 min-max 变换放大。当前最符合证据的结构是双入口反馈环：局部 value bias 可被搜索放大；搜索调度也可在 value 首次判断没有明显错误时独立制造动作错误。随后 `env/core/run_env.py::_adapt_native_neural_result` 把 Full-Gumbel `root_policy` 作为历史字段 `visit_policy` 返回，`rl/algorithms/accumulating_ppo.py` 又把 `result["visit_policy"]` 写入 combat replay 的 policy target，因此搜索制造的偏差能被训练回 policy prior。value 则使用每场战斗结束时统一填充的 final combat HP target，具有延迟、高方差和稀有低 HP/斩杀边界覆盖不足的问题。增加训练量可能改善 value 校准，却不会从原理上消除 Bash 已展示的搜索入口；若搜索 target 持续反馈，单纯堆训练还可能把错误变得更稳定。

## 无文字因果探索游戏概念设计

用户原始意图：基于当前训练中“敌人低 HP 与较差局面被回合数/受击次数混杂”和“按怪物槽位而非实体身份泛化击杀顺序”的现象，设计一个完全没有文字描述、由颜色深浅和符号构成、能诱发并测量人类/模型认知错误的游戏。

本轮范围为概念设计，不修改训练、环境或评测代码。提出“无言色界 / Chromatic Causality”：回合制三目标竞技场，颜色亮度表示数值强度，色相表示潜在实体家族，形状表示能力，脉冲表示当前意图，位置只表示槽位；机制保持可发现但不提供文字标签。核心实验关包括回合时钟与低 HP 的混杂、槽位启发式在换位后的失效、延迟触发/错误击杀顺序、付出生命换信息的探索决策和搜索候选早期淘汰的路径依赖。

建议分为盲玩、可控干预、换位/换色迁移和反相关对抗四阶段；记录同 HP 不同回合、同实体不同槽位、直接策略与后继搜索动作等指标，区分归因错误、错误泛化、更新滞后、探索效率和搜索放大。设计约束是每条规则都有稳定视觉不变量、结果反馈不能用文字代替、颜色不作为唯一信息通道，并在模拟器内部保留实体 ID/槽位/真实因果变量以支持反事实验证。未实现原型，后续若立项应先做三实体四动作的确定性 MVP。

## 无文字设计的比较边界补充

用户进一步明确：不能把人类的游戏理解过程直接当作模型的理解过程。人类通常带有大量语言、游戏规则和图标语义先验，而从像素/状态转移训练的模型可能没有任何对应的机制概念；无文字游戏的核心是移除人类的语言规则入口，迫使人类主要依赖本局探索经验形成先验。

因此后续设计应避免剑/盾/眼睛、红色危险/绿色治疗、数字血条等熟悉隐喻，使用每个被试随机生成且跨局重新映射的抽象视觉词汇；目标和反馈只通过可见状态变化表达。模型基线应使用与人类相同的视觉输入和动作接口、随机初始化视觉编码器及明确交互预算，不输入实体 ID、规则标签或文字预训练语义。比较对象应是干预下的行为、迁移和反事实一致性，而不是语言解释或“是否理解游戏”。

建议设立 human-no-text、human-text-control、scratch-visual-agent、pretrained/symbolic-agent 四个条件，分别估计语言先验、视觉归纳偏置和探索经验的影响；所有机制、槽位、实体身份和真实因果变量仍在模拟器内部单独记录，不能从玩家/模型动作序列反推机制理解。未实现代码。

## 从肉鸽/战斗隐喻迁移到全新环境

用户指出，类《杀戮尖塔》的肉鸽结构本身会激活人类的卡牌、回合、敌人、血量、房间和升级先验，因而仍然不是纯粹的探索学习环境。本轮设计方向改为“无言色场”：没有角色、敌人、回合、卡牌、地图、掉落或持久升级，玩家直接操纵一个连续演化的颜色场和其中的抽象自组织结构。

建议的最小环境是一个中央结构与若干会移动、合并、分裂、发波的抽象色结；玩家通过匿名几何手势对局部施加脉冲、旋转、阻隔或观察扰动，目标是让中央结构保持可见的稳定形态。亮度、饱和度、轮廓、脉冲和空间关系分别承载不同状态变量；低亮度/高危险由全局相位或延迟蓄力造成，实体身份与位置解耦，探索动作本身会改变场。每次试验独立重置，无关卡/肉鸽进程，成功或失败只通过中央结构的聚合/崩解反馈。

该方向保留低强度与危险混杂、位置启发式、延迟归因和探索成本等认知陷阱，但把研究对象从“战斗策略”换成“对动力系统的干预”。后续应先验证抽象色场是否能在没有任何熟悉游戏隐喻的情况下形成稳定、可复现的错误假设；未实现代码。

## 保留肉鸽宏观层、重造局内状态概念
