## End-turn leaf disabled value check

User intention: verify whether training receives the required value after End Turn
when `end_turn_as_leaf` is disabled. This was read-only code inspection plus
bounded native/training regression testing; runtime code was not changed.

Findings: with the flag false, C++ executes End Turn through the enemy turn and
draw/recharge, then requests the resulting state as a regular network leaf
(`needs_policy=true`). Python evaluates and backprops that leaf value. The
search `root_value` is diagnostic; replay `value_target` remains NaN until the
fight ends, when all pending roots receive final normalized combat HP. No value
is lost; the post-turn state is an ordinary leaf/root rather than a special
boundary sample.

## Training action contract and Strike root diagnosis

User intention: confirm whether training policy receives a joint card+target
action or selects the card and target sequentially, and explain the screenshot
where the model selected Strike while Acid Slime was using a non-attacking Lick.

Static contract: `env/core/action_space.py` defines targeted plays as two thin
timesteps, `PLAY_CARD[h]` followed by `PICK_TARGET[t]`; only the second resolves
`ga.combat(actions.encode_play(h, t))`. `env/core/run_env.py:621-631` returns
immediately with zero reward while a partial play is pending and calls the thick
backend only after the target step. `SplitStSPointerPolicy.forward/evaluate_actions`
uses one masked categorical distribution over the frozen action-id table, so each
environment timestep contributes one action id. The regular collector delegates
to the MaskablePPO collector; the NOSL-AZ collector likewise writes the selected
thin id to `rollout_buffer.add` once per env step. The native NOSL search is a
separate protocol: it searches complete card+target simulator actions and maps
the selected native action back to one thin root card id; this bypasses the
ordinary pending-target step when committed.

The loaded checkpoint metadata confirms the active training variant is
`nosl_is_az=true`, `nosl_is_az_cpp=true`, and `nosl_is_az_inner_only=true`.
In this path `sim/sts_lightspeed/src/sim/search/NoslCombatTrainer.cpp:1136-1157`
maps every complete card+target action to the card-slot root id, while
`env/core/run_env.py:1035-1078` aggregates all target variants into the thin
root policy target. `_train_nosl_is_az` consumes only observation/mask/policy
target/value target arrays shaped by the thin action table; it does not add a
separate target-step policy sample. Thus current NOSL-AZ combat training is
joint inside search but card-root-only at the learner interface. The ordinary
PPO/direct path remains genuinely two-step and trains a separate target
transition.

Reproduction (CPU, native extension) selected `PLAY_CARD + 2` in the custom
Large Slime state. The first step reported `reward=0`,
`pending=('play', 2)`, unchanged backend state, and legal mask `[PICK_TARGET+0]`.
The next target step changed backend state (energy 1 -> 0, monster HP 57 -> 48)
and returned to `arg_step=root`. Verification:
`uv run --no-sync pytest -q tests/integration/test_training_smoke.py tests/integration/test_run_v2.py`
(`6 passed`).

The live dashboard state at `runs/local/dashboard-state-now.json` was a direct
capture of the screenshot condition: `ACID_SLIME_L_LICK`, 80/80 player HP,
1 energy, hand Defend/Clash/Strike/Wild Strike, Full Gumbel 512 simulations,
`gumbel_scale=0`, and `gumbel_rescale_q=false`. Root search values were Strike
raw Q `0.338636`, Wild Strike `0.329644`, End Turn `0.334574`, Defend `0.327765`;
their priors were `0.7160`, `0.2811`, `0.001805`, `0.001124`. Full Gumbel's
within-root `log(prior)+completed-Q` therefore selected Strike (displayed
completed score `7.8609` vs Wild `6.7082`, End Turn `1.7796`, Defend `1.1412`).
The non-attacking intent does not force End Turn: policy/search optimize the
learned future value, not a hand-coded intent rule, and the root Q estimate
already ranked Strike highest in this state.

Q comparability: with `gumbel_rescale_q=false`, `raw_q` remains on the common
value-head scale (here 0..1 normalized combat HP), so raw Qs are semantically
comparable across nodes only when model/value target/perspective and search
conditions are the same. `normalized_q` is still sibling min-max diagnostic

## Value boundary supervision audit

User intention: assess the hypothesis that End-Turn and combat-victory boundary
states are search boundaries but may not become supervised value samples, so
the value network must extrapolate there.

The distinction is real in the NOSL-AZ collector. Every actual non-terminal
combat root is stored with a search policy target and an initially unknown value
target. When the real fight ends, all roots from that fight receive the exact
final player HP target. Neural search leaves are evaluated and backed up but are
not inserted into replay; assigning the selected trajectory's outcome to
hypothetical leaves would be invalid.

End-Turn boundary supervision is implemented but conditional. The environment
always attaches the stable post-enemy-turn boundary observation to an actual
native End Turn. The collector appends it as a value-only sample with
`policy_weight=0` only when `nosl_is_az_end_turn_as_leaf=true`. The dashboard
checkpoint inspected in this task stores that flag as false, matching
`configs/train/nosl_paper_replay_fresh10_20260913.args`, while the screenshot
search used it as true. Thus checkpoint `3379200` was trained on next-turn
normal roots rather than the intermediate boundary but was later asked to
evaluate that boundary in the dashboard. This is a concrete train/inference
distribution mismatch. The newer `configs/train/nosl_rootpaper_replay.args`
does enable the flag and therefore collects actual-path End-Turn boundaries,
but not hypothetical search leaves.

Terminal combat states are handled differently. Native search detects the
terminal outcome and backs up exact `current player HP / 200` without a network
request. Collection labels the last pre-kill root and all earlier actual roots
with the same exact final-HP target, but does not add the post-kill terminal
observation itself. This is sufficient for current search correctness because
the network is never consulted at terminal nodes, but the network's output on a
terminal-shaped observation is necessarily extrapolated if another consumer
requests it.

A bounded counterfactual on the current checkpoint changed only
`post_enemy_turn_boundary` from 0 to 1 in the fixed Cultist observation. Value
changed from `0.3736456037` to `0.3565051258` (delta `-0.0171404779`). That
synthetic combination is not a legal boundary state, so it does not prove the
real boundary prediction is wrong; it does show the unsupervised boundary input
can materially affect value.

Persistent follow-up is VAL01 in `TODO.md`: measure sample coverage and
calibration by root/boundary/terminal kind, decouple boundary replay collection
from the search truncation choice for a controlled experiment, and never label
hypothetical leaves with the executed line's eventual return. No runtime or
training configuration was changed. This section accompanies the current local
documentation commit.
