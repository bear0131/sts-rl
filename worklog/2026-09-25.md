### Loss sensitivity diagnosis from matched LR curves

User observation: despite a threefold LR difference, the two value-loss
curves nearly overlap after the early updates while policy loss remains
separated.

The implementation explains this asymmetry.  The combat value target is one
normalized terminal HP value assigned to every root in a fight
(`rl/algorithms/accumulating_ppo.py:63-72`), and the value branch has its own
MLP/head after the combat encoder (`rl/policies/split_policy.py:879-889` and
`:971-973`).  The policy target is a per-root masked search distribution, so
its cross-entropy gradient is the logit residual `p-q` over many actions.  A
scalar HP regressor therefore reaches the conditional-regression floor much
faster; Adam's normalized steps then make a larger nominal LR less visible in
the residual MSE.  The search target is also regenerated between collections,
so policy fitting continues to have a moving/high-dimensional target.

The logged diagnostics are not the same as the weighted optimizer objective.
The actual NOSL loss is `policy_coef * cross_entropy * policy_weight +
value_coef * MSE` (`accumulating_ppo.py:2109-2114`), with defaults `1.0` and
`0.5`.  Value diagnostics include all roots, including value-only
boundary/terminal samples, while policy diagnostics filter to positive policy
weights (`accumulating_ppo.py:2192-2198`); their denominators are respectively
all sampled roots and policy-weight sum (`:2241-2244`).  Thus visual overlap of
the two scalar curves does not imply equal branch gradients.

At matched update 78, the raw rank-0/aggregated records were:

| metric | LR `1e-4` | LR `3e-4` |
|---|---:|---:|
| value loss | 0.00382 | 0.00331 |
| value MAE | 0.04169 | 0.04029 |
| value-target std | 0.14625 | 0.13899 |
| policy loss | 0.92319 | 0.67548 |
| target policy KL | 0.43022 | 0.27357 |
| target top1 agreement | 0.65382 | 0.78801 |

The weighted scalar policy term is already roughly two to four hundred times
larger than the weighted value term at these points (`0.675 / (0.5*0.00331)`
for the high-LR run, with the caveat that the metrics use different sample
denominators).  Therefore the graph supports “policy fitting is the current
bottleneck,” but does not by itself prove that policy coefficient should be
increased.  A coefficient change must be tested separately at fixed LR, or
validated with policy-only/value-only gradient norms; the production run was
not modified.
