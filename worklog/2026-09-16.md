## Packed leaf 大合法动作集修复与四机 replay 恢复

用户原始意图：“帮我快速查一下训练为什么停止了并修好 bug 重启训练”。范围限定为定位本次
`u40x4-20260915` 四机退出、修复直接根因、保留 replay 并以同一搜索/训练配置和 W&B run 恢复；
没有调参、创建新实验或丢弃 replay。

首个实质错误出现在 rank1：`RuntimeError: NOSL compact legal-action row exceeds fixed width`；
rank0/rank2 随后发生 ring receive timeout，rank3 为 ring peer closed，均是 rank1 worker 退出后的
连锁反应。`next_batch_packed()` 曾把每个 leaf 的合法动作矩阵硬编码为 128 列，但原生牌堆使用
`std::vector`，Exhume/Headbutt 等从消耗堆或弃牌堆选牌的状态可以合法地产生超过 128 个动作。
本次没有截断动作，而是按当前 leaf batch 的最大合法动作数分配连续矩阵，并继续用逐行 count
标识有效前缀；count 同步改为 `uint32`。Python 消费端原本已经按二维矩阵实际宽度和 count 读取，
运行逻辑无需改变。

新增 native 回归构造一张 Exhume 加 129 张 Strike 的消耗堆，先让搜索打出 Exhume，再验证普通
`next_batch()` 与 packed 路径均返回 129 个且 action bits 逐项相同。本地明确加载
`build-gumbel-current` 后，目标回归通过；`test_search_contracts.py`、`test_nosl_fast_step.py`、
`test_nosl_tree_labels.py` 合计 `27 passed, 1 xfailed`，xfail 为既有 F05。四台远端的训练虚拟环境
没有 pytest，因此分别执行了同构的直接 Python smoke，四台都实际得到并对齐 129 个动作。
